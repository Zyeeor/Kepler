# 新怪物生成配置测试指南

面向策划与关卡配置人员，适用于正式测试场景 `EnemyAiTest`。本文说明局内持续刷怪模式的当前配置、验证方法与验收标准。

## 1. 模式开关

在场景的 `WaveManager` 上配置：

| 开关 | 结果 |
|---|---|
| `continuousSpawning = true` | 使用持续刷怪规则：普通怪速率曲线、分钟上限、类型轮换、方向替换、7 条可配置精英投放与 7 分钟 Boss。 |
| `continuousSpawning = false` | 使用原逻辑：原有 `CountKill` / `Timed` 波次、清场、选卡流程。 |

有 `RoomTemplate` 接管的房间始终保留原有房间波次流程。持续刷怪模式中已移除怪潮和击杀回响；击杀普通怪不会额外生成怪物。

## 2. 当前默认规则

默认罪印轮换顺序为：

```text
傲慢 → 怠惰 → 暴食 → 嫉妒 → 愤怒 → 贪婪 → 色欲 → 循环
```

| 规则 | 默认值 / 行为 |
|---|---|
| 普通怪生成速率 | `normalSpawnRateByMinute` 默认从第 0 分钟的 `1/3` 只/秒线性增长到第 7 分钟的 `7/3` 只/秒。速率为 `r` 时，间隔为 `1 / r` 秒；速率为 0 时暂停普通怪生成。 |
| 普通怪同时存在上限 | `continuousSpawnMaxCountsByMinute = [10, 20, 30, 30, 30, 30, 30]`，分别对应 `[0,1)` 至 `[6,7)` 分钟。精英怪不占用该上限。 |
| 普通怪类型 | 按 `continuousSpawnOrder` 的 `sin` 成功轮换。一次生成因上限、全局保护或位置失败而未成功时，不跳过该类型。 |
| 移动方向影响 | 保留原有按玩家移动方向替换一只其它类型普通怪的功能；它只调整场上构成，不改变自动生成的轮换顺序。 |
| 精英怪 | `continuousSpawnOrder` 默认包含 7 条投放：30、90、150、210、270、330、390 秒。每条可独立设置类型、生成时间、生命值系数与攻击力系数。 |
| 生命成长 | `monsterHealthMultiplierByMinute` 默认从第 0 分钟的 `1` 线性增长到第 7 分钟的 `2.4`。新生成怪物（含精英与 Boss）生命值 = 基础生命值 × 当前曲线值。 |
| 攻击成长 | `monsterAttackMultiplierByMinute` 默认从第 0 分钟的 `1` 线性增长到第 7 分钟的 `1.84`。新生成怪物（含精英与 Boss）攻击力 = 基础攻击力 × 当前曲线值。 |
| Boss | `nonBossDurationSeconds = 420` 秒。到时停止非 Boss 刷怪并尝试生成 Boss。 |
| 全局保护 | `MonsterSpawner.maxCombatMonsters` 仍是普通怪的额外安全上限；非存活状态的普通怪不会占用持续刷怪的普通怪同时存在上限。 |

普通怪上限已满时，系统不会补发此前错过的生成；空出名额后，从下一次正常调度继续尝试生成。

## 3. Inspector 配置说明

### WaveManager

| 字段 | 用途 |
|---|---|
| `continuousSpawning` | 开启持续刷怪模式。 |
| `normalSpawnRateByMinute` | 横坐标为战斗分钟数（建议覆盖 0 到 7），纵坐标为平均每秒普通怪生成数。运行时会换算为 `1 / r` 秒生成 1 只。 |
| `continuousSpawnMaxCountsByMinute` | 必须配置 7 个非负整数，依次对应第 0～6 分钟的普通怪同时存在上限。 |
| `continuousSpawnOrder` | 7 条连续投放数据。普通怪按各条的 `sin` 顺序轮换；每条同时定义该罪印精英的 `eliteSpawnTimeSeconds`、`eliteHealthMultiplier`、`eliteAttackMultiplier`。默认 7 条对应 7 个罪印。 |
| `directionalReplacementEnabled` | 是否保留移动方向驱动的类型替换。 |
| `sectorReplacementDistance` | 触发方向替换所需的主动移动距离；0 表示使用当前镜头水平屏幕直径。 |
| `sectorReplacementCountPerTrigger` | 每次方向替换可替换的最多普通怪数量。 |
| `monsterHealthMultiplierByMinute` | 横坐标为战斗分钟数（建议覆盖 0 到 7），纵坐标为生命值系数；新生成怪物生命值 = 基础生命值 × 当前系数。 |
| `monsterAttackMultiplierByMinute` | 横坐标为战斗分钟数（建议覆盖 0 到 7），纵坐标为攻击力系数；新生成怪物攻击力 = 基础攻击力 × 当前系数。 |
| `nonBossDurationSeconds` | 非 Boss 阶段时长；当前规则使用 420 秒。 |

普通怪生成速率曲线可设为 0 以暂停生成；生命与攻击系数应保持大于 0。不要通过怪潮或击杀奖励补怪。

`continuousSpawnOrder` 每条精英的最终数值为：

```text
生命值 = 基础生命值 × 当前 monsterHealthMultiplierByMinute × eliteHealthMultiplier
攻击力 = 基础攻击力 × 当前 monsterAttackMultiplierByMinute × eliteAttackMultiplier
```

投放时间以战斗开始后的秒数计算，不再依赖每分钟的固定秒数。建议按时间从小到大排列；若多个条目设为同一时间，系统会分别尝试投放。每条精英最多尝试一次，即使因位置、全局保护或网络失败未能生成，也不会在之后补发。

### MonsterSpawner

| 字段 | 用途 |
|---|---|
| `continuousSpawnMaxCount` | 运行时由 `WaveManager` 按当前分钟同步的普通怪上限；通常不需要单独手调。 |
| `maxCombatMonsters` | 普通怪的全局安全上限，独立于精英怪。 |
| `spawnSectorOrder` | 各怪物类型对应的屏幕边缘生成扇区。 |
| `killEchoScreenPadding` | 虽沿用历史字段名，当前用于连续普通怪和精英怪的屏幕边缘生成留白。 |

## 4. 测试步骤

### A. 普通怪频率、上限与类型轮换

1. 打开 `EnemyAiTest` 并开启 `WaveManager.continuousSpawning`。
2. 将 `normalSpawnRateByMinute` 临时设为全程 `0.5` 只/秒，并将 7 个上限设为足够大；确认普通怪约每 2 秒生成 1 只。将曲线改为 `1` 只/秒后，应约每秒生成 1 只。
3. 将曲线设为 0，确认普通怪停止自动生成；重新设为正值后，确认正常恢复。
4. 将当前分钟的普通怪上限临时设为 2，确认普通怪达到 2 只后停止；清理 1 只后，确认系统在下一次调度时继续生成，且不会一次性补发遗漏怪物。
5. 将 `continuousSpawnOrder` 设为至少 3 种类型，记录连续成功生成的类型，确认按顺序循环且失败生成不会跳过类型。
6. 以镜头正前方为基准，将视角旋转到七个方向，确认每种罪印在自己的扇区内、屏幕外且靠近屏幕边缘的合法位置生成。
7. 在场上有不可见的其它罪印普通怪时，让玩家沿某一方向主动移动并触发替换，确认场上类型构成向目标方向对应罪印倾斜；随后继续观察自动生成，确认其轮换顺序未被替换逻辑改写。
8. 连续击杀普通怪，确认只会按正常曲线调度刷怪，不会因击杀额外生成怪物。

### B. 分钟上限、精英与数值

1. 使用默认上限数组，确认第 0 分钟上限为 10、第 1 分钟为 20、第 2～6 分钟为 30。
2. 将普通怪上限压满并等待 30、90、150 秒，确认对应配置的精英仍各尝试生成 1 只。
3. 将第 2 条的 `eliteSpawnTimeSeconds` 临时改为 45，确认精英在第 45 秒而非固定分钟偏移出现；将其 `sin`、生命/攻击系数改为不同值，确认生成类型和数值按该条配置生效。
4. 确认精英怪不会占用普通怪上限，也不会因普通怪全局数量管理而被阻止。
5. 将生命曲线与攻击曲线均设为全程 `1`，生成普通怪并记录其 `maxHealth`、`spawnDamageMultiplier`，确认分别等于基础生命值、`1`。
6. 将生命曲线设为全程 `2`、攻击曲线设为全程 `1.5`，生成普通怪，确认其生命值为基础生命值的 2 倍、攻击系数为 `1.5`。
7. 在不同时刻生成怪物，确认每只怪在生成时快照当前曲线值；之后修改曲线或推进时间，不会重置已在场普通怪的生命和攻击数值。

### C. 7 分钟与旧逻辑回归

1. 将战斗推进至 420 秒，确认普通怪和精英怪停止调度，并进入 Boss 尝试生成流程。
2. 关闭 `continuousSpawning` 后重新 Play，确认旧 `CountKill` / `Timed` 波次、清场和选卡流程仍可运行。
3. 在持续刷怪模式下确认不存在怪潮倒计时、怪潮批量生成、击杀回响生成等日志或行为。
4. 在 `EnemyAIAttackTestSpawner` 保持关闭的情况下完成以上测试，避免旧测试刷怪器重复注入。

## 5. 常见问题

| 现象 | 优先检查 |
|---|---|
| 普通怪没有生成 | 曲线当前时刻的值是否大于 0、当前分钟普通怪上限是否已满、`maxCombatMonsters` 是否触发，以及屏幕边缘是否有可用生成点。 |
| 自动生成类型看起来不是严格轮换 | 自动生成按成功生成顺序轮换；玩家移动方向替换会改变场上已有怪物的类型构成，这是预期行为。 |
| 普通怪已满仍会出现精英怪 | 普通怪上限和精英怪独立管理。配置时间到达的精英不计入普通怪同时存在数量。 |
| 数值成长不符合预期 | 检查两条数值曲线在当前战斗分钟的系数；该系数仅在怪物生成时快照，已在场普通怪不会因时间推进而重算。 |
| 旧字段找不到 | 持续刷怪模式已移除怪潮、击杀回响和固定普通怪间隔配置。请改用 `normalSpawnRateByMinute` 曲线和 `continuousSpawnMaxCountsByMinute` 数组。 |

## 6. 验收重点

- 新旧逻辑可以通过 `WaveManager.continuousSpawning` 独立切换。
- 普通怪频率完全由 0～7 分钟的速率曲线控制，普通怪同时存在上限由 7 项分钟数组控制。
- 普通怪按类型平均轮换生成；方向替换功能仍然有效且不破坏轮换调度。
- 7 条精英投放均可独立配置类型、时间、生命与攻击系数；精英不占用普通怪数量上限；不存在怪潮。
- 击杀普通怪不会触发额外刷怪。
- 新生成怪物的生命值、攻击力分别等于各自基础数值乘以当前分钟的生命、攻击曲线系数；已在场普通怪保留生成快照。
- 战斗到 7 分钟后停止非 Boss 刷怪并进入 Boss 流程。
