# DEC-CANON-20260820-005 — 数据驱动叙事旁白与教学Delivery Contract

- **Date:** 2026-08-20
- **Owner status:** Approved

## Decision

当前Demo正式采用数据驱动的叙事旁白、双线文本显示与教学Delivery Contract，使程序可先开发通用系统，策划后续可自行增删旁白、替换音频和文案、调整Access与Card显示触发、配置教学Step，而无需修改底层Gameplay代码。

## Narrative / Voice

- 旁白成为Mythic / System双线的核心低成本Delivery载体；
- Mythic众神声与System电子声是两个独立Presentation Channel，不自动定义为两个独立世界人格；
- 首个成功Run交付System、Certification、Version、Instance与User Distillation核心真相；
- 后续Run使用Certified Lineage / Version Trials低频Recognition深化；
- Narrative Access、Trigger Event与Display Mode解耦；
- A0–A4具体绑定Wave、Elite、Card、Possession或自定义事件的规则配置化；
- Elite保留为递进旁白与A3候选条件，但不作为底层硬编码的唯一入口；
- Card可配置显示Neutral / Mythic / System / Follow Access版本；Card ID、图标、Gameplay效果和中性机制摘要稳定。

## Voice / Text / Audio Delivery

- 所有玩家可见叙事文本使用稳定Text Key；
- 最终术语使用Concept Key映射Neutral / Mythic / System版本；
- 所有音频使用稳定Audio ID；
- Voice使用独立通道，不占用Gameplay SFX池；
- Cue支持单句、多句顺序组合、优先级、重复范围、高压战斗繁忙策略、BGM Duck与调试；
- 字幕支持None / Optional / Forced；普通旁白不要求常驻字幕，关键Reveal必须有可靠文字承载；
- 具体旁白、音频和文案数量不冻结。

## First Clear / Run Analytics

- 保留现有First Clear八段结构；
- 三个Self-Declaration为可配置文本，只表达玩家态度，不改变胜负、Build、评分、结局或能力；
- 程序采集每个Sin的Body控制、Possession、三槽使用和Card投资，以及全局换身、Soul / Shrine、Bullet Time、Elite与Final等原始数据；
- 主 / 次倾向权重、行为句式、阈值和平局处理配置化；
- Model / Version / Instance使用可替换模板，最终玩家格式后补。

## Tutorial

- TUT-01 / 02为初始Pride取得控制后的短准备段；
- TUT-03 / 04 / 05嵌入正常Wave与真实战斗；
- TUT-06 / 07与Monster微教学按真实条件延迟触发；
- Tutorial Controller贯穿整个Run；
- 教学关闭时隐藏表现并自动放行阻塞；
- 玩家提前操作可追溯完成，Step结算幂等；
- Step完成后跨Run持久化，未完成Step不保存半步状态；
- 首个教学Corpse与下一合法Body机会具备最低Encounter保障；
- 按键提示读取实际Input Binding；
- Monster微教学优先显示关键机制，三槽详情可展开；
- 教学需有超时、目标失效、死亡、读档、UI冲突兜底与调试工具。

## Conflict resolution

旧Presentation写法把A3直接绑定为：

> Elite / high-value transfer → A3

本Decision保留A3的信息权限与Elite叙事价值，但取消底层唯一硬编码：

> A3由Narrative Access Profile中的可配置条件推进；Elite / high-value transfer是合法候选，不是唯一条件。

## Not frozen

- 具体Access触发；
- Card具体切换节点；
- Cue与音频 / 文案总数；
- Self-Declaration最终文案；
- Functional Summary精确权重与词库；
- Model / Version / Instance最终格式；
- 最终术语、字幕、音色、混音与教学时间参数。

## Follow-up

程序开发Task应基于两份Delivery Baseline定义技术方案与验收，至少覆盖：

- Text / Terminology配置；
- Audio / BGM配置；
- Narrative Cue / Access / Display；
- Voice播放与调度；
- Run Analytics与Profile；
- Tutorial Step / Controller；
- 统一调试工具。

程序内部类名、ScriptableObject布局、事件总线、Localization实现和存档Schema进入Technical ADR / Task Contract，不由本Decision固定。
