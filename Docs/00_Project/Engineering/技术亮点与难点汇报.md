# Possession 项目技术亮点与难点汇报

> 汇报日期：2026-08-28

## 项目概述

《Possession》不是传统的“固定角色刷怪”框架。它把灵魂、怪物躯体、技能、卡牌、程序化地图和叙事状态放进同一套运行时体系：玩家可以在战斗中频繁更换身体，敌方与附身后的玩家又必须复用相同能力，同时保证世界流送、随机结果、存档与性能都不失控。项目真正有价值的部分，是把这种高变化玩法拆成了可重复执行的工程合同。

## 技术亮点

### 1. 附身不是“换皮”，而是控制权的统一转移

项目以 `Actor + IController` 作为控制骨架，`SetController` 是灵魂、怪物和特殊控制效果切换控制权的统一入口。附身时不需要复制一套“玩家怪物代码”，而是把玩家控制器交给目标躯体；脱离后再恢复 AI 或空控制器。这样既让敌人与玩家复用移动、受击和技能执行，也把魅惑、拉扯、倒地、尸体等复杂状态纳入同一生命周期。

这套设计的难点不在接口本身，而在切换前后的清理：AI 决策、正在释放的技能、动画更新时间、阵营、碰撞、血条和尸体状态都必须同步恢复，否则很容易出现“身体换了，旧逻辑还在跑”的隐蔽问题。

### 2. Tag、Effect、Ability 和卡牌形成数据驱动战斗闭环

`GameplayTagContainer` 使用来源归属和引用计数管理状态。同一个 Tag 可以由多个技能或效果同时授予，移除其中一个来源不会误删其他来源的状态。在此基础上，`CombatAbilityComponent` 统一处理能力、效果和状态门禁，卡牌则通过能力 Tag 定向改变参数。

这让敌人原生技能与玩家附身技能可以走同一条执行链，也让“跨躯体保留什么、离体清掉什么”能够用明确规则表达，而不是散落在大量角色脚本里。对后续扩充怪物和卡牌来说，这是比单个技能效果更重要的可维护性基础。

### 3. 四级地图流送兼顾连续世界与单帧预算

`MapStreamingSystem` 将周边区块分成 A/B/C/D 四级范围：完整模拟、场景待机、纯逻辑预加载和卸载缓冲分别处理。流送任务按类型和距离排序，同时受“每类任务数量上限”和 8ms 单帧时间片双重约束；离开区域时保存 `ChunkState`，被 Pin 的关键区块则不会被错误回收。

这套方案解决的不是单纯的加载问题，而是高速移动时的峰值控制。区块实例化、AI 激活、快照保存和对象回收被拆成可以跨帧消化的状态机，避免某一次跨区把所有昂贵操作堆到同一帧。

### 4. 随机系统按领域隔离，问题可以稳定复现

`SeedSystem` 从单局世界种子派生 Card、Wave、AI 三类独立随机流，同一领域再用 salt 区分波次、房间或怪物。地图、卡牌、刷怪和部分 AI 因此可以在同一种子下复现，同时又不会因为“多抽了一张卡”意外改变下一波怪物。

这项实现直接提升了程序化内容的可调试性：策划可以复现具体局面，开发可以对同一输入比较优化前后结果，自动化测试也有稳定前提。当前仍有少量遗留 AI 使用全局随机，属于已识别的后续收口项。

### 5. 怪物 AI 面向流送世界，而不是依赖固定烘焙场景

普通怪物通过降频决策、行为树和自定义寻路行动；寻路会读取地形危险区，并结合空间桶做群体分离，适配动态生成和卸载的地图。Boss 则由 `BossCombatBrain` 对候选能力按距离、视线、状态条件和最近使用历史评分，避免连续重复技能，并能在多次无解时触发战术位移。

亮点在于 AI 不只问“能不能放技能”，还考虑技能家族、理想距离、前置状态和历史节奏。它更接近一个可解释的战斗导演，也便于针对不同怪物逐步增加规则。

### 6. AI 怪物技能开发管线把设计到落地串成可审计流程

项目引用的 `monster-dev-pipeline` Skill，不是简单地让 AI 根据一句描述直接生成代码，而是把怪物开发拆成三段：

1. Stage A 只以 Canonical 为设计真源，将概念整理为可执行的怪物开发规格；AI 会主动“找茬”，补齐状态、资源、时序和边界。必要补全必须标记为 `[AI裁定]`，硬冲突则停止，不会偷偷改成新设定。
2. Stage B 将已确认规格映射为 Ability、Effect、Tag、Card、Prefab 配置、测试说明和完成状态，并固定普通怪物三槽技能关系，减少设计、代码和资源之间的信息损耗。
3. Stage C 只在 Owner 明确发出“提交某怪物”一类命令时进入受限提交路径。本次任务没有触发该阶段，也没有提交或推送代码。

这条管线的价值，是让 AI 生成从“写一段代码”升级为“产出有依据、可追踪、可复查的完整怪物能力包”。换一个 Agent 也能从同一规格继续工作，适合持续扩充大量差异化怪物。

### 7. 叙事、时间与运行状态采用独立调度

运行状态负责保存世界种子、卡牌、躯体和关键进度；叙事调度器处理队列、优先级、暂停与一次性触发；时间缩放则由独立管理器协调暂停、命中停顿等来源。它们没有直接绑死在某个场景或怪物脚本上，降低了“战斗暂停把叙事卡死”“切场景后状态丢失”这类系统耦合问题。

## 本轮性能优化落地

本轮对 `Assets/Scripts` 的 255 个 C# 文件、约 5.2 万行代码进行了静态审计，并选择最确定、最少改变玩法语义的热点落地：

- Actor 滑动移动、通用投射物和地雷的高频 `Physics.OverlapSphere` 改为复用缓冲的 NonAlloc 查询；只需要布尔结果的位置改用 `CheckSphere`，减少持续数组分配。
- `TerrainEffectTile` 建立启用实例注册表，`MonsterPathfinder` 不再每 0.25 秒扫描整个场景寻找危险地块；离开地块时的临时列表也改为复用缓冲。
- `MonsterActor` 缓存 AI、Animator、Boss 尸体表现和血条相机引用，同时保留暴食状态组件“首次释放技能后才动态挂载”的兼容逻辑。
- `VfxPool` 把池对象的粒子系统层级扫描缓存到 `PooledObject`，VFX 重复租借和归还时不再反复分配数组。

优化过程刻意保留了原有伤害、技能节拍和多 Collider 结算语义。实现后又由独立 Review Agent 检查缓存失效、池化生命周期、注册表对称性和 NonAlloc 缓冲边界，并对发现的问题直接修正。

目前可以确认的是目标热路径中的分配型 API 与全场景扫描已经移除；不能确认具体 FPS 或 GC 百分比提升。当前 Unity-MCP 会话认证异常，尚未取得可靠的 Play Mode Profiler 对照数据，因此量化结论必须等固定 Seed、固定压测场景下补采。32/64 容量的 Collider 缓冲也需要在极端密集场景中观察是否打满。

### 本轮新增的渲染与加载优化

针对“战斗进行几分钟后画面负载和首刷尖峰叠加”的问题，又完成了一轮以运行时开关为中心的 GPU 与加载优化：

- A1–A4：粒子、Trail、范围圈和瞬态 VFX 关闭阴影；怪物主体在屏幕外动态停止阴影投射；Trail 限制顶点距离与寿命；怪物 Animator 使用 `CullUpdateTransforms`；关闭怪物/VFX 子层级的非 Directional 灯光。
- B5：Telegraph、斩击、范围圈等瞬态表现共享材质，颜色通过 `MaterialPropertyBlock` 写入，并为支持的材质开启 GPU Instancing，避免 `Renderer.material` 在运行时生成材质实例。
- B6：Chunk 视觉构建完成后，仅对满足 MeshFilter/MeshRenderer 条件的静态地形做 Static Batching；粒子、Trail、Line 和动态 VFX 明确排除。
- GameManager 将 A1–A4、B5、B6 以及既有动态阴影、GPU Instancing、共享瞬态材质路径集中为可切换开关，便于压测时做单项对照；新生成对象和场景加载后的对象统一走同一策略入口。
- 选卡界面成为加载窗口：`MonsterPreloadService` 从刷怪表和怪物技能 Effect 的序列化引用建立目录，每帧预热一个怪物或 VFX Prefab 到对象池，选卡关闭或切场景时可取消，重复选卡会补足池容量。

这轮优化的亮点不在于“把所有 Renderer 一刀切”，而在于先捕获资源原始状态，再按对象类别应用策略：怪物本体、特效、静态地形和池化瞬态对象各走不同规则，关闭开关仍能回退。独立 Review Agent 已复核阴影分类、静态合批过滤、预加载可取消性和 Unity 构造阶段初始化风险。当前编译为 0 个错误、66 个 Warning；由于 Unity-MCP 认证异常，GPU 批次数、真实 FPS 与 GC 下降幅度仍需在 Player/Development Build 中用固定 Seed 的 `profile.data` 复测，不能把预期收益写成实测结论。

## 核心技术难点

项目最难的地方，是多个“正确性”同时成立：附身前后身份和控制权要正确，流送前后世界状态要一致，程序化随机既要有变化又要可复现，怪物能力要足够不同但仍能进入统一框架，性能优化还不能悄悄改变战斗手感。

因此工程重点不是追求单点炫技，而是建立稳定边界：控制器只从统一入口切换，随机数按领域隔离，区块按状态机流送，技能以 Tag/Effect 表达规则，怪物开发以 Canonical 和可执行规格为准，性能修改则用“语义不变”作为第一验收条件。这些边界让复杂玩法可以继续扩展，而不会随着内容数量增长迅速失控。

## 汇报结论

当前项目已经形成一套较完整的“玩法创新 + 工程化生产”能力：附身机制提供核心差异化，流送与确定性随机支撑可持续关卡，AI 管线把怪物设计转成可复用的生产流程，性能工作则同时覆盖 CPU/GC 热路径、GPU 几何与阴影预算，以及首波怪物/VFX 加载峰值。下一步最有价值的工作，是补齐固定场景的性能基线，并继续处理技能 Physics 查询、寻路 open list 和 UI 轮询三类规模化热点。
