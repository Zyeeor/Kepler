# 怪物生成配置指南

面向策划与关卡配置人员。本文说明当前 Unity 工程中普通怪物、全局压力补刷、击杀回声和精英怪的生成配置方式。

文档版本：2026-08-24
适用场景：当前地图流送 / 波次战斗流程

> 设计原则以 `.vibe/doc/Canonical/` 为准。本指南记录当前工程实现，其中 Encounter / Spawn 的精确数值仍属于 `TUNABLE / PLAYABLE`，最终以实机体验为准。

## 1. 先理解生成链路

当前地图战斗中，怪物生成由几条链路共同作用：

```text
WaveManager.waves
        │
        ▼
WaveConfig.weightedTable
        │ 按权重抽取
        ▼
MonsterWaveDef
        │ 编队组成 + 组内数量
        ▼
MonsterSpawner.TryGetWaveSpawnPosition
        │ 合法地形 / 玩家周围环带 / 组中心
        ▼
MonsterPool.Spawn
        │
        ▼
MonsterActor
```

同时还有：

- `RunSpawnDirector`：按战斗时间维持全局压力，并处理玩家击杀后的 Kill Echo 额外生成。
- `EliteBuildDirector`：按波次节奏投放精英怪，并从 Catalog / Preset 恢复精英构筑。
- `MonsterSpawner.maxCombatMonsters`：所有波次怪、压力怪和精英共享的全场在场上限。

策划调参时，应先判断要调整的是“本波内容”“全局压力”“击杀回声”还是“精英投放”，不要混用入口。

## 2. 配置文件与组件位置

| 配置对象 | 常见位置 | 主要用途 |
|---|---|---|
| `MonsterWaveDef` | `Assets/Settings/MapStreaming/Waves/` | 定义一组刷哪些怪、每种几只 |
| `WaveConfig` | `WaveManager.waves` 列表 | 定义本波抽哪些编队、权重、总数 / 时长 |
| `WaveManager` | 战斗场景中的 `WaveManager` | 控制波次节奏和过波条件 |
| `MonsterSpawner` | 战斗场景中的 `MonsterSpawner` | 控制全场配额、普通刷怪距离和合法取点 |
| `RunSpawnDirector` | 战斗场景显式挂载或运行时自动创建 | 控制全局压力、Kill Echo、Boss时间 |
| `EliteBuildDirector` | 战斗场景显式挂载或运行时自动创建 | 控制精英投放、精英倍率和 Catalog |
| `EliteMonsterCatalog` | 通常为 `Resources/EliteMonsterCatalog.asset` | Sin 与精英 Prefab / Preset 的映射 |

### 2.1 场景中没有 Director 时

`WaveManager` 会自动确保 `MonsterSpawner` 和 `RunSpawnDirector` 存在；`EliteBuildDirector` 也支持运行时自动创建。

如果希望策划直接在 Inspector 调整 `RunSpawnDirector` 或 `EliteBuildDirector`，建议在战斗场景中显式挂载对应组件。显式场景组件会优先成为运行时实例；否则使用脚本字段默认值。

## 3. 创建普通怪物编队

### 3.1 创建 `MonsterWaveDef`

在 Project 窗口中选择：

```text
Create → Kepler → Map → Monster Wave
```

建议放在：

```text
Assets/Settings/MapStreaming/Waves/
```

配置字段：

| 字段 | 含义 | 策划建议 |
|---|---|---|
| `id` | 编队唯一标识 | 使用易读名称，例如 `wave_w1_pride_gluttony` |
| `monsters` | 编队内怪物列表 | 每行绑定一个普通怪物 Prefab，并填写数量 |
| `monsters[].prefab` | 怪物 Prefab | 使用正式的 `*_new` Prefab，确认挂有 `MonsterActor` / `Enemy` |
| `monsters[].count` | 抽中该编队时生成的数量 | 这是“组内数量”，不是本波总数 |
| `spawnWeight` | 旧的编队级权重字段 | 当前波次流程不使用；不要用它调本波比例 |
| `statMult` | 编队属性倍率预留字段 | 当前实现暂未应用，不要把它当作有效的血量 / 伤害调参入口 |

编队示例：

```text
Wave_W1_Basic
  monsters:
    Pride_new     count = 1
    Gluttony_new  count = 2
```

抽中这组编队后，会先找一个合法的组中心，再在中心附近散射生成 3 只怪。

### 3.2 将编队加入 `WaveConfig`

在战斗场景的 `WaveManager.waves` 中展开每一波，配置 `weightedTable`：

| 字段 | 含义 |
|---|---|
| `weightedTable[].def` | 引用一个 `MonsterWaveDef` |
| `weightedTable[].weight` | 本波抽中该编队的相对权重 |
| `totalCount` | 数量波累计生成的怪物总数 |
| `duration` | 时间波持续时间，单位秒 |
| `maxSpawnCount` | 时间波累计生成上限；`0` 表示不限制 |
| `doublePick` | 本波完成后是否连续选择两张卡 |

权重只比较相对大小。例如：

```text
编队 A：weight = 3
编队 B：weight = 1
```

表示抽取倾向约为 3:1，不是 3% 和 1%，也不会影响其他波次对同一编队的权重。

### 3.3 `totalCount` 如何计算

`totalCount` 按实际怪物个体数量计算，而不是按编队次数计算。

例如一个编队包含：

```text
Pride_new count = 2
Wrath_new count = 1
```

抽中一次就累计生成 3 只。若本波 `totalCount = 10`，最后一次抽取可能会被裁剪，只生成尚未达到总数的部分。

## 4. 波次节奏配置

### 4.1 `WaveManager` 字段

| 字段 | 当前默认值 | 作用 |
|---|---:|---|
| `waveMode` | `CountKill` | 全部波次统一使用数量波或时间波 |
| `groupScatterRadius` | `3` | 同一编队内怪物围绕组中心的散射半径，单位米 |
| `spawnInterval` | `0.5` | 两次补刷之间的间隔，单位秒 |
| `pruneInterval` | `0.1` | 清理死亡 / 附身怪并更新本波在场列表的间隔 |
| `choiceBuffer` | `2` | 波次结束到选卡前的缓冲时间，单位秒 |
| `autoShowChoiceUI` | 开启 | 波次完成后自动打开选卡界面 |
| `recycleRemainingOnTimeUp` | 开启 | 时间波结束时回收剩余普通怪 |
| `gracePeriod` | `2` | 第一波开始前准备时间，单位秒 |
| `autoStart` | 开启 | 场景加载后是否自动开始 |
| `autoStartTimeout` | `30` | 等待地图流送就绪的最长时间，单位秒 |

### 4.2 数量波 `CountKill`

数量波的流程是：

1. 按 `spawnInterval` 补刷。
2. 直到累计生成达到 `totalCount`，停止本波新增。
3. 等待本波怪物全部死亡、附身或退场。
4. 清场后进入选卡 / 下一波。

适合用于需要明确“本波刷多少只”的关卡。

### 4.3 时间波 `Timed`

时间波的流程是：

1. 在 `duration` 秒内持续补刷。
2. `maxSpawnCount = 0` 时不设本波累计生成上限，只受全场配额限制。
3. `maxSpawnCount > 0` 时，达到上限后停止新增。
4. 时间到后按 `recycleRemainingOnTimeUp` 决定是否回收剩余普通怪。

适合用于生存、持续压力或最终阶段。时间波与数量波不能在同一个 `WaveManager` 中混用，`waveMode` 是整体配置。

### 4.4 正式连续战场的配置边界

- 波次唯一配置入口是战斗场景中的 `WaveManager.waves`。
- 波次刷点范围由 `MonsterSpawner` 的地图流送与合法取点逻辑决定。
- 不再通过旧房间蓝图覆盖波次配置。

## 5. 普通怪物生成位置

普通波次由 `MonsterSpawner.TryGetWaveSpawnPosition` 取点，要求：

- 位于玩家周围 `minSpawnDistanceToPlayer` 到 `maxSpawnDistanceToPlayer` 的环形带内；
- 所在 Chunk 已加载，且 Tile 可走；
- 默认排除相机正前方 60° 扇形，降低怪物直接贴脸出现的概率；
- 同一编队先生成一个中心点，再由 `groupScatterRadius` 做组内散射。

`MonsterSpawner` 主要字段：

| 字段 | 代码默认值 | `CombatTest` 当前值 | 作用 |
|---|---:|---:|---|
| `maxCombatMonsters` | `30` | `30` | 全场怪物硬上限，普通怪 / 压力怪 / 精英共享 |
| `minSpawnDistanceToPlayer` | `20` | `20` | 普通波次最近生成距离，单位米 |
| `maxSpawnDistanceToPlayer` | `50` | `50` | 普通波次最远生成距离，单位米 |
| `spawnHeightY` | `0` | `0` | 初始生成高度；池化系统随后会将胶囊底部校正到地面 |
| `killEchoScreenPadding` | `0.75` | 默认 | Kill Echo 越过屏幕边缘后的额外距离，单位米 |
| `upkeepInterval` | `0.25` | `0.25` | 追踪表修剪间隔，单位秒 |

### 5.1 普通波次调参建议

- 想让怪物更早进入战斗：减小 `minSpawnDistanceToPlayer`，但不要让其进入玩家可见区或攻击起手范围。
- 想让怪物更分散：增大 `maxSpawnDistanceToPlayer` 或 `groupScatterRadius`。
- 想保持编队可读性：优先减小 `groupScatterRadius`，不要先大幅提高刷新频率。
- `maxCombatMonsters` 太小会导致波次补刷、压力刷怪和精英投放互相抢配额。

## 6. 全局压力与击杀回声

`RunSpawnDirector` 不等同于某一波的 `WaveConfig`。它在 Waves / Final 战斗阶段按全局战斗时间运行，使用当前在场数量作为压力参考。

### 6.1 周期压力补刷

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `pressureInterval` | `8` | 周期压力检查间隔，单位秒 |
| `earlyTarget` | `6` | 战斗前 120 秒的全局目标在场数 |
| `midTarget` | `8` | 120–300 秒的全局目标在场数 |
| `lateTarget` | `11` | 300 秒后的全局目标在场数 |
| `earlyPerTick` | `2` | 前期每次最多补刷数量 |
| `midPerTick` | `3` | 中期每次最多补刷数量 |
| `latePerTick` | `4` | 后期每次最多补刷数量 |
| `normalPrefabs` | 运行时填充 | 从当前有效波次的编队中收集普通怪 Prefab |

实际补刷数量取决于：

```text
min(本次最多补刷数量, 全局目标在场数 - 当前 TrackedMonsterCount)
```

因此它不会无视 `maxCombatMonsters` 无限增加怪物。

### 6.2 击杀回声 Kill Echo

玩家附身状态下击杀普通怪，会进入 Kill Echo 窗口，符合条件时延迟生成一只普通怪：

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `maxEchoesPerWindow` | `4` | 一个窗口内最多成功生成的回声数量 |
| `echoWindowSeconds` | `10` | 回声计数窗口，单位秒 |
| `echoMinDelay` | `0.6` | 生成延迟下限，单位秒 |
| `echoMaxDelay` | `1.1` | 生成延迟上限，单位秒 |
| `echoExpirySeconds` | `2` | 请求超过该时间仍未生成则过期 |

当前 Kill Echo 的位置规则：

1. 取上一只被击杀怪物的位置和玩家当前位置。
2. 从“死亡怪物 → 玩家”方向经过玩家延长射线。
3. 找到屏幕边缘外最近的合法可走 Tile。
4. 新怪与死亡怪物、玩家三点共线。
5. 新怪生成后立即朝玩家移动，不等待普通 AI 的随机决策节拍。

`killEchoScreenPadding` 越小，怪物越贴近屏幕边缘；越大，越不容易在生成瞬间被发现，但进入战斗会更晚。

当前代码的触发条件是：玩家处于附身状态并造成 PlayerDamage Fatal，且死亡对象不是被附身对象、不是 Boss。Boss 明确不会触发 Kill Echo；Elite 当前没有单独排除，因此玩家击杀精英也可能消耗 Kill Echo 名额并生成一只普通怪。若设计上要求“精英击杀不触发回声”，需要另行补充程序规则。

## 7. 随战斗时间增强的数值

当前 `RunSpawnDirector.CurrentTier` 每 30 秒提升 1 级：

```text
Tier = floor(ActiveCombatSeconds / 30)
```

普通怪生成时会按当前 Tier 快照数值：

| 项目 | 公式 | 上限 |
|---|---|---:|
| 最大生命值 | `1 + Tier × 0.10` | `3.0x` |
| AI 伤害 | `1 + Tier × 0.06` | `2.2x` |

参考值：

| 战斗时间 | Tier | HP倍率 | 伤害倍率 |
|---:|---:|---:|---:|
| 0 秒 | 0 | 1.00x | 1.00x |
| 30 秒 | 1 | 1.10x | 1.06x |
| 300 秒 | 10 | 2.00x | 1.60x |
| 480 秒 | 16 | 2.60x | 1.96x |
| 600 秒 | 20 | 3.00x | 2.20x |

这套时间成长会与精英倍率相乘。不要再把同样的波次成长重复写进怪物 Prefab 基础属性，否则会造成双重膨胀。

## 8. 精英怪投放配置

精英怪不是普通编队中的另一种普通怪。正常流程由 `EliteBuildDirector` 根据波次节奏投放，并通过 `EliteMonsterCatalog` 找到对应 Prefab。

### 8.1 投放节奏

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `eliteEnabled` | 开启 | 精英系统总开关 |
| `eliteStartWave` | `3` | 从第几波开始允许投放；默认 W1–W2 不投放 |
| `eliteEveryNWaves` | `2` | 推荐 W3 / W5 / W7 投放节奏 |
| `finalWaveEliteChance` | `0.8` | 最后一波的投放概率，非硬保证 |
| `waveGap` | `1` | 精英历史快照至少比当前请求波次高出的波次数 |
| `catalog` | Catalog 资产 | Sin → Prefab / Preset 映射 |

Canonical 规则要求精英占用 Pressure Budget，不作为免费额外密度。当前工程已落实的是精英与普通怪共享 `MonsterSpawner.maxCombatMonsters`，并计入本波清点；目前没有独立的可配置 `Threat Cost / Pressure Budget` 字段。同一波默认不超过一个精英。

### 8.2 精英强化参数

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `eliteHealthMultiplier` | `2` | 相对当前波次普通怪的最大生命值倍率 |
| `eliteAttackDamageMultiplier` | `2` | 相对当前波次普通怪的攻击伤害倍率 |
| `eliteVisualScaleMultiplier` | `2` | 视觉尺寸倍率，只缩放视觉节点 |

实际精英最大生命值可理解为：

```text
普通怪基础生命值 × 当前战斗时间成长倍率 × 精英生命倍率
```

攻击伤害同理。战斗时间 Tier 提升时，精英当前生命值 / 最大生命值比例保持不变，不会因为成长刷新而直接回满。

精英不读取当前 Run 的 Basic / Global / Monster-Type / Type Growth 卡层，只保留自己的历史构筑快照。

### 8.3 精英 Catalog 配置检查

每个正式 Sin 至少检查：

- Catalog 中有对应条目；
- `prefab` 指向正式 `*_new` 怪物 Prefab；
- Prefab 上存在 `MonsterActor` / `Enemy`、AI 和必要能力；
- 本地 `presetSnapshots` 需要在离线或服务器空候选时提供可用兜底；
- 不要把精英 Prefab 直接放入普通 `MonsterWaveDef`，除非是专项压力测试。

## 9. 测试与调参入口

### 9.1 运行时快捷键

在调试场景打开怪物作弊面板：

| 按键 | 作用 |
|---|---|
| `0` | 随机生成普通怪 |
| `1–7` | 生成并附身对应普通怪 |
| `8` | 召唤 Boss |
| `9` | 从 `EliteMonsterCatalog` 的 Preset 中随机生成精英 |

`9` 键生成的精英会沿用 `EliteBuildDirector` 的 HP / ATK / Scale 参数，适合单独检查精英表现和数值。

### 9.2 推荐测试顺序

1. 先只配置一个 `MonsterWaveDef`，确认 Prefab 能正常生成和移动。
2. 再增加第二个编队，验证 `weight` 比例是否符合预期。
3. 调整 `totalCount` / `duration`，确认过波条件正确。
4. 调整 `minSpawnDistanceToPlayer`、`maxSpawnDistanceToPlayer`，观察生成位置是否仍在可读范围外。
5. 最后打开周期压力和 Kill Echo，避免多个系统同时变化导致无法判断原因。
6. 单独按 `9` 检查精英，不要用普通波次结果判断精英 Catalog 是否正确。

## 10. 常见问题

### Q1：我改了 `MonsterWaveDef.spawnWeight`，为什么本波比例没变？

当前波次流程使用的是 `WaveConfig.weightedTable[].weight`。`MonsterWaveDef.spawnWeight` 是旧 / 备用字段，不参与当前波次抽取。

### Q2：我改了 `MonsterWaveDef.statMult`，为什么怪物属性没变？

该字段目前只是预留，当前实现未应用。普通怪数值应使用战斗时间成长；精英数值应使用 `EliteBuildDirector` 的精英倍率。

### Q3：我把 `totalCount` 调大了，但场上怪物没有增加。

检查以下限制：

- `MonsterSpawner.maxCombatMonsters` 是否已达到；
- 当前是否还有未回收的尸体 / 精英尸体占用追踪配额；
- 生成点所在 Tile 是否可走、Chunk 是否已经加载；
- `spawnInterval` 是否过大；
- 全局 `RunSpawnDirector` 是否已经达到目标在场数。

### Q4：同一编队里的怪物为什么聚在一起？

这是当前编队设计：先生成组中心，再按 `groupScatterRadius` 散射。想让编队更松散可增大该值，但应注意障碍物和可读性。

### Q5：精英为什么没有出现？

依次检查：

- 当前波次是否小于 `eliteStartWave`；
- 是否命中 `eliteEveryNWaves` 或最后一波概率；
- `eliteEnabled` 是否开启；
- `EliteMonsterCatalog` 是否存在有效 Preset / Prefab；
- `MonsterSpawner.maxCombatMonsters` 是否已满；
- 是否因为没有合法刷怪点而跳过。

### Q6：Kill Echo 没有出现在屏幕边缘。

Kill Echo 需要同时满足：

- 怪物确实由玩家附身状态击杀；
- 回声窗口未达到 `maxEchoesPerWindow`；
- 请求没有过期；
- 屏幕外射线方向存在已加载且可走的 Tile；
- 全场配额未满。

## 11. 策划验收清单

- [ ] 每个正式 `MonsterWaveDef` 都引用了正确的 `*_new` Prefab。
- [ ] `WaveConfig.weightedTable` 的权重比例符合本波意图。
- [ ] `MonsterWaveDef.spawnWeight` 和 `statMult` 没有被误当成当前有效配置。
- [ ] 数量波的 `totalCount`、时间波的 `duration / maxSpawnCount` 已明确。
- [ ] 波次补刷间隔和组内散射不会造成怪物堆叠或突然贴脸。
- [ ] `maxCombatMonsters` 能同时容纳普通怪、尸体、压力怪和精英。
- [ ] Kill Echo 生成位置在屏幕外、离玩家合理，并且生成后会立即追击。
