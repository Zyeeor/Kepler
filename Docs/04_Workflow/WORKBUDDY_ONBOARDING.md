# WorkBuddy Onboarding

The `Possession Development` GitHub Project and its Issues are the team's daily Task entry point.

For a normal team member:

```text
Open Possession Development
→ Read the GitHub Issue
→ Confirm Assignee / Executor
→ Move the Issue to Doing
→ Ask WorkBuddy to start the Task ID
→ Work on work/<TASK-ID>-description
→ Self Check
→ Move to Review
→ Professional / Integration Review
→ Done
```

Before the first Task, read `AGENTS.md`, `.vibe/rules.md`, and this file. For each Task, read the GitHub Issue first. If it links a Detailed Contract under `Tasks/`, read that Contract as mandatory context. Small, low-risk Issue-only Tasks do not need a placeholder Markdown file.

Work on a Task branch created from the latest `main`, not directly on `main`. Ask the Agent to report Goal, Scope, Out of Scope, files, plan, tests, risks, requirement conflicts, and Shared Original impact before editing. If an Issue-only Task does not contain enough information to work safely, complete the Issue instead of asking the Agent to invent missing rules.

New members do not need rebase, cherry-pick, reflog, worktree, CI internals, or advanced merge knowledge on day one. Escalate conflicts and high-risk shared-asset work to the Professional Owner.
