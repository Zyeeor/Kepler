# 荣誉殿堂：简单功能开发案

## 1. 目标

在主菜单提供“荣誉殿堂”入口，用于长期回顾玩家在各局中构筑出的七宗罪怪物，并展示其来源局表现与被投放到其他玩家对局后的异步战绩。

- 仅用于记录与展示，不提供任何战斗加成。
- 荣誉记录独立于 Elite 投放候选库，长期保存且不受候选库 FIFO 淘汰影响。

## 2. 界面功能

| 区域 | 功能 |
| --- | --- |
| 标题栏 | 显示“荣誉殿堂”、记录总数、手动刷新按钮与关闭按钮。 |
| 排序栏 | 支持按保存时间、杀怪数、造成 Run Fail 次数、BD 卡牌数量排序；默认按保存时间倒序。 |
| 记录列表 | 纵向滚动展示可点击的荣誉记录；每条记录对应 `playerId + runId + sin`。 |
| 单条记录 | 展示所属罪、保存时间、来源局阶段、构筑深度、控制时长、击杀数与异步战绩摘要；点击整条记录打开详情。 |
| 记录详情 | 全屏详情页或弹窗展示完整构筑、原始 Run 表现、异步传播战绩与历史版本提示；关闭后保留原列表的排序、页码与滚动位置。 |
| 滚动条 Slider | 根据当前页可滚动内容量动态调整滑块长度；内容未超出可视区域时隐藏或禁用。 |
| 分页 | 支持上一页、下一页与当前页码显示。 |
| 状态反馈 | 覆盖 Loading、空列表、网络错误与离线缓存四种状态。 |

### 2.1 记录详情交互

- 点击列表中的任意记录，进入该记录的详情视图；整行均为可点击区域。
- 详情顶部显示所属 Sin、保存时间、来源局阶段与构筑深度，并提供返回/关闭按钮。
- 详情内容分为“原始 Run 表现”和“异步传播战绩”两个独立区块，完整展示对应字段。
- 卡牌区域展示完整卡牌清单、数量与失效标记；失效卡显示“历史版本 / 部分内容已失效”，但不阻断详情打开。
- 返回列表后恢复此前的排序、页码与滚动位置。

> 参考界面中的“入侵次数”可映射为“被投放次数”。跨玩家影响统一以“造成 Run Fail 次数”表达，避免使用“击败玩家人数”。

## 3. 数据设计

### 3.1 荣誉记录 `HallRecord`

| 分类 | 字段 | 说明 |
| --- | --- | --- |
| 标识 | `playerId`、`runId`、`sin` | 单条荣誉记录的唯一身份。 |
| 原始 Run 表现 | `savedAt` | 保存时间。 |
| 原始 Run 表现 | `sourceStage` | 来源局到达阶段。 |
| 原始 Run 表现 | `buildDepth` | 该 Sin 的构筑深度。 |
| 原始 Run 表现 | `cardIds` | 携带卡牌 ID 列表。 |
| 原始 Run 表现 | `controlDuration` | 本局控制该怪物的总时长。 |
| 原始 Run 表现 | `killCount` | 该怪物在来源局中的击杀数。 |
| 异步传播战绩 | `deployedCount` | 被投放次数。 |
| 异步传播战绩 | `fatalCount` | 被其他玩家击杀次数。 |
| 异步传播战绩 | `possessedCount` | 被其他玩家附身次数。 |
| 异步传播战绩 | `bodyFatalCount` | 造成 Body Fatal 次数。 |
| 异步传播战绩 | `runFailCount` | 直接导致 Run Fail 次数。 |
| 兼容信息 | `contentVersion` | 记录创建时的内容版本。 |
| 兼容信息 | `isHistorical`、`hasInvalidContent` | 标记历史版本或含失效内容的记录。 |

### 3.2 基础横幅资源映射

- 每条记录根据其 `sin` 加载对应的怪物基础横幅，作为记录卡片的背景视觉主体。
- 横幅只承担怪物身份识别，不表示构筑强度、战绩高低或卡牌稀有度；实际数值仍以正文数据为准。
- 横幅由 `sin` 在运行时映射，不随单条记录重复存储；横幅更新后，同类历史记录同步使用新版资源。
- 无法识别的 `sin` 或缺失资源统一回退为中性“历史记录”横幅，保证旧数据仍可浏览。

## 4. 核心流程

1. **Run 中采集**：某个 Sin 首次拥有至少一张卡牌后建立快照，并持续更新卡牌、击杀、控制时长与构筑深度。
2. **Run 结束写入**：成功、失败或中断时，冻结该局已构筑 Sin 的快照并写入长期 Profile 存档；未携带卡牌的临时附身怪物不生成记录。
3. **打开界面**：优先读取并展示本地缓存，再请求异步战绩更新；网络不可用时保持本地浏览能力。
4. **手动刷新**：重新请求异步战绩；请求失败时保留现有列表，仅提示错误或离线状态。
5. **历史兼容**：卡牌删除、改版或 ID 无法解析时，记录仍可查看，并标记“历史版本 / 部分内容已失效”。

## 5. UI 表现建议

- 使用深色背景、香槟金边框与罪别彩色竖条，保持参考图的庄严档案感。
- 每条记录以所属怪物的基础横幅作为卡片背景视觉主体，横幅上叠加半透明深色遮罩，确保文字与数据清晰可读。
- 每条记录以罪别色作为左侧识别条；罪别色仅代表所属 Sin，不表示卡牌稀有度。
- 将数据明确分为两个区块：
  - 原始 Run 表现：冷蓝标签；
  - 异步传播战绩：暖橙标签。
- 列表默认仅展示摘要；卡牌完整清单与详细数据可通过展开或详情弹窗查看，避免列表过度拥挤。

## 6. 开发范围

### 本期实现

- 主菜单入口与关闭返回；
- 本地长期存档；
- 荣誉记录列表、排序、分页与滚动；
- 按 Sin 映射的七类怪物基础横幅及中性历史记录回退横幅；
- 可点击的记录详情页，支持查看完整构筑与全部统计；
- 本地缓存优先、手动刷新、离线与错误状态；
- 历史记录兼容展示；
- 本地模拟数据，用于完整 UI 流程验证。

### 后续对接

- Elite 投放后的真实战果回传；
- 服务端同步与跨设备数据恢复；
- 调试入口：重置记录、模拟联网状态、注入测试战绩。

### 不在本期范围

- 排行榜、好友对比、玩家搜索；
- UGC 浏览、下载或编辑；
- 任何影响战斗属性的奖励系统。

## 7. 验收标准

- 每局中每个携带至少一张卡牌的 Sin，在结束后生成且仅生成一条记录。
- 成功、失败与中断的 Run 均能保留已构筑记录。
- 默认按保存时间倒序，可正确切换四种排序。
- 每条记录根据所属 Sin 正确显示对应基础横幅；横幅缺失时安全回退为中性历史记录横幅。
- 点击任意记录可查看完整详情，返回后列表状态保持不变。
- 断网时仍可查看本地缓存。
- 异步数据只展示真实战果回传，不以本地推测补全。
- Elite 候选库清理或 FIFO 淘汰不会删除荣誉殿堂记录。
- 删除或改版卡牌不会导致旧记录读取失败。
