# 1. Purpose

本文件定义当前Demo的局外（Meta / Out-of-Run）系统必须表现出的行为、需要持久化的数据、以及验收标准。

本文件冻结系统行为与数据语义，不冻结程序类名、存储引擎、网络协议、精确阈值或最终文案。

---

# 2. System Boundary

当前局外界面系统只有两个：

1. **卡牌图鉴（Card Archive）**：记录玩家见过、取得过的Card，提供回顾。
2. **荣誉殿堂（Hall of Records）**：长期展示玩家构筑出的代表性怪物及其异步战绩。

以下**不属于**局外界面系统：

- **Elite投放链路**：战斗内投放「他人构筑的精英怪」是核心玩法与数据侧，不是主菜单局外界面；
- **UGC创作平台**：本期不开发浏览界面、编辑器、下载后可玩等内容；服务器已有内容存储能力可保留，但不对玩家开放前端。

三个系统共享 `playerId / runId / sin / cardId`，但使用不同生命周期的数据，不得混用同一份会互相淘汰的存储。

---

# 3. Shared Foundation

以下能力被两个局外界面与Elite链路共同依赖，应作为统一基础设施：

- **长期Profile存档**：与Run存档分离，保存图鉴、荣誉、身份、设置等跨局数据；
- **匿名玩家身份**：设备级 `playerId`；局级 `runId`；
- **局外入口与导航**：主菜单统一入口，一致返回逻辑；
- **通用列表组件**：列表、详情、筛选、排序、分页；
- **状态组件**：Loading / Empty / Error / Offline；
- **网络与缓存**：请求失败降级本地数据，支持手动刷新；
- **内容版本兼容**：Card / Monster 删除或改版后，旧数据仍可安全展示；
- **统一调试**：强制解锁、重置图鉴 / 荣誉、模拟联网状态。

# 4. Card Archive（卡牌图鉴）

## 4.1 定位

只记录与展示，不提供任何战斗加成。

## 4.2 三态可见性

| 状态 | 含义 | 可见内容 |
|---|---|---|
| 未知 | 从未在Offer中显示 | 仅剪影 |
| 已知 | 在Offer中显示过但未选择 | 卡面 + 名称 + 效果说明 |
| 已解锁 | 玩家正式选择过 | 完整信息 + 取得标记 / 首次取得时间 / 取得次数 |

- 「已知」可以查看效果说明：效果说明在游戏内Offer选卡时已向玩家展示，图鉴只是回顾，不构成剧透；
- 「未知」才应隐藏，作为真正的收集目标；
- 三态不使用「已发现 / 已取得」等替代词，沿用「未知 / 已知 / 已解锁」。

## 4.3 数据字段

每张Card至少持久化：

- `seen`（是否已知）；
- `unlocked`（是否已解锁）；
- `firstSeenAt`（首次显示时间）；
- `firstUnlockedAt`（首次取得时间）；
- `selectedCount`（跨Run取得次数，即「取得次数」而非「效果触发次数」）；
- `isNewUnread`（是否仍有未查看的新标记）。

## 4.4 分类

顶层分类：

- 七宗罪Monster（各自一页）；
- 「通用」独立页（承载Basic Universal与Global Slot卡）。

## 4.5 进度与牌池

- 进度分母 = 当前有效Card总数；
- 被禁用（disabled）的Card不进入当前总数；
- 删除的Card默认不显示，但保留玩家历史记录，必要时标记为历史版本；
- 牌池更新后自动迁移分母，不得清空玩家既有记录。

## 4.6 记录时机

- Card在Offer中显示即记录「已知」；
- 玩家确认选择即记录「已解锁」，不依赖通关；
- 失败Run同样保留记录。

## 4.7 双线显示

- First Clear前默认Mythic；
- First Clear后默认System，并允许玩家手动切换Mythic / System；
- 中性机制摘要始终显示；
- 两套语言保持「一事两译，机制唯一」。

## 4.8 新卡提示

- 新发现 / 新取得时，对应分类入口显示红点；
- 玩家进入对应怪物页、且该Card实际进入可见区域后清除；
- 进入图鉴首页不清除全部红点。

## 4.9 验收

- 玩家先于选择看到Card，仍正确标记「已知」；
- 删除Card后分母自动更新且不丢失玩家历史；
- 失败局仍保留发现与取得记录；
- 图鉴不提供任何战斗加成。

# 5. Hall of Records（荣誉殿堂）

## 5.1 定位

只做构筑回顾与长线成就感，不提供任何战斗加成。

## 5.2 记录单位与身份

- 记录身份 = `playerId + runId + sin`；
- 每个Run中，每个「携带Card数量 ≥ 1」的Sin形成一条记录；
- 对局内持续更新该Sin快照，Run结束后冻结为荣誉记录；
- 不记录未携带Card的临时附身怪物。

## 5.3 生命周期

- 长期永久保留；
- 使用独立于Elite投放候选库的存储；
- 不受Elite候选库容量FIFO淘汰影响。

## 5.4 数据字段

原始Run表现：

- 保存时间；
- 来源Run与到达阶段；
- 该Sin的BD深度；
- 携带的Card清单与数量；
- 本局控制该怪物的总时间；
- 本局击杀数。

异步传播战绩（来自他人游戏）：

- 被投放次数；
- 被其他玩家击杀次数；
- 被其他玩家Possess次数；
- 造成Body Fatal次数；
- 直接导致Run Fail次数。

原始Run表现与异步战绩分开展示，不混用同一字段名。

## 5.5 统计语义

- 不统计「击败过的玩家人数」——当前无账号体系，只有设备身份；
- 使用「造成Run Fail次数」表达对其他玩家游戏的影响；
- 「总击杀数」统一为「该怪物在本Run来源局的击杀数」，不与其他语义混用。

## 5.6 排序

统一排序字段：

- 保存时间；
- 杀怪数；
- 击败玩家数（以造成Run Fail次数计）；
- BD卡牌数量。

默认按保存时间倒序。

## 5.7 数据更新

- 玩家自己的记录：Run结束立即写入/更新；
- 异步战绩：进入荣誉殿堂时，先显示本地缓存，再联网刷新，并支持手动刷新；
- 不要求每次返回主界面都强制刷新。

## 5.8 数据来源

异步战绩依赖Elite战果回传（见 §6.5），服务器需要知道每只被投放的精英怪后续发生了什么。

## 5.9 边界

- 分页；
- 离线缓存；
- 空状态、网络错误状态；
- Card删除 / 改版后，历史记录标记为「历史版本 / 部分内容已失效」，仍可查看。

## 5.10 验收

- 记录不会被Elite候选库容量淘汰；
- 失败局仍能留下已构筑怪物的记录；
- 断网仍能查看本地荣誉记录；
- 异步战绩字段来自真实战果回传，非推测。

# 6. Elite Delivery Chain（核心玩法数据侧）

本链不属于局外界面，但作为核心玩法与荣誉殿堂的数据来源，其行为合同在此一并锁定。

## 6.1 快照格式

- `bdData` = 已取得的Card ID清单（唯一获取，`stack` 恒为 1）；
- `bdCount` = 清单长度；
- 不包含Basic / Global卡；
- 以Canonical `Stack Max = 1`为准，任何「层数」表述作废。

## 6.2 Build深度

- 跨Sin比较使用标准化深度：`已取得该Sin Card数量 / 该Sin当前合法Card总数`；
- 筛选先按标准化深度分档，再参考原始`bdCount`与`sourceWave`；
- 精确权重可调。

## 6.3 投放来源

- 在线真实快照优先；
- 服务器无网或候选库为空时，使用本地Preset Elite兜底；
- 兜底不改变Run流程，也不产生Gameplay buff。

## 6.4 投放节奏

- 投放节点、频率、概率为可配置Encounter参数；
- 默认配置需与当前Playable基线一致。

## 6.5 战果回传

Elite被投放到他人游戏后，需要回传至少：

- Elite成功生成；
- Elite Fatal；
- Elite被Possess；
- Elite造成Body Fatal；
- Elite直接导致Soul Death / Run Fail。

该回传是荣誉殿堂「异步战绩」字段的数据来源。

## 6.6 版本与失效

- 快照携带 `contentVersion`；
- 注入端遇到无法识别的Card ID时静默跳过，并重算有效深度；
- 旧快照引用已删除Card不应导致解析失败。

## 6.7 sourceWave语义

- `sourceWave` = 快照拍摄时已完成的Wave；
- Final上传使用独立阶段标记，不长期借用虚构Wave编号。

## 6.8 验收

- 无网也能刷出精英怪（本地Preset）；
- 跨Sin不会因牌池大小产生明显偏置；
- 旧快照含失效Card不会导致解析失败；
- 战果回传能支撑荣誉殿堂异步战绩展示。
