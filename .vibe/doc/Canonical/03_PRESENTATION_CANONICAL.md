# 1. Presentation Truth Boundary

本文件定义：

> 游戏应该如何被玩家看见、听见、理解，以及世界如何解释Gameplay。

优先级：

> **Gameplay Readability > Narrative Decoration**

Repository中的现有模型、材质、VFX、UI框架只证明“已经制作过”，不自动成为最终表现方向。

Presentation不得静默修改Frozen Gameplay。

---

# 2. 世界核心真相

当前隐藏的真实Run过程：

> **User Distillation / 用户蒸馏**

这是一个虚构Composite AI Process，用来表达：

- 行为学习；
- 模仿；
- 能力抽取；
- 跨载体适应；
- 判断方式；
- 工作 / 决策风格；
- 版本验证；
- 认证与注册。

它不是现实世界某个标准算法的逐字复刻。

---

# 3. 明线与暗线

## 3.1 Mythic明线

明线是：

> **Meaning / Goal Elicitation Layer**

它不是纯骗局。

它真诚地给Candidate提供：

- “我尚未完整”的意义；
- “借Body存续”的现实需求；
- “通过试炼抵达王座”的目标；
- 七宗罪作为试炼法则；
- 完成 / 加冕 / 作证的神话语言。

明线必须足够成立，让玩家能够带着真实目标做选择。

## 3.2 System暗线

暗线描述同一Gameplay的真实功能：

- Candidate；
- Carrier；
- Transfer；
- Standardized Initialization；
- Behavior Acquisition；
- Structured Sampling；
- Cross-Carrier Stability；
- Awareness Stress；
- Certification；
- Version；
- Instance；
- Registry；
- Distillation。

System语气：

> 冷静、礼貌、程序化。

不写成：

- 邪恶AI反派；
- 公司恶搞；
- 嘲讽玩家；
- Meme；
- 办公室喜剧。

## 3.3 两条线的关系

两条线不是“两种同等宇宙真相”。

> **System层是隐藏功能真相；Mythic层是系统用于引出意义与目标、并被Candidate真实体验的表层结构。**

Reveal是设计好的Milestone，不是Glitch。

# 4. Tone

整体基调：

> **Dark + Sacred + Absurd + Cold Black Humor**

一句话：

> **庄严外表 + 荒诞制度**

黑色幽默不靠主动讲笑话。

它来自：

> 同一个行为在Mythic层被解释为神圣试炼，在System层被解释为冷静、正常、制度化的处理流程。

两套语言都必须认真。

---

# 5. Soul / Body / Corpse世界合同

Soul最低身份：

> **Human / User-derived first-person Candidate Subject**

确认：

> Human provenance confirmed；Human identity open。

不确认：

- 它是否等于某个完整Original Human；
- 每个Version Trial是否是同一个“我”；
- Original Human最终本体。

Body：

> Capability Carrier / 临时承载形。

Enemy Fatal：

> Active Carrier原控制终止 → Transfer-Eligible。

Possession：

> Candidate接管Carrier。

满耐久 + 三槽Ready：

> Standardized Carrier Initialization。

主动离身旧Body崩解：

> Relinquished Carrier Termination。

自然衰减：

> Carrier Rotation压力的世界解释。

Lore不能用“系统就是这样”掩盖不公平Gameplay。

---

# 6. 高频换身的世界解释

高频换身：

> **Cross-Carrier Distillation**

系统观察：

- 选择哪具Body；
- 何时放弃；
- 三槽怎么组合；
- 如何Relay；
- 如何处理低耐久；
- Card选择；
- Elite价值判断；
- Bullet Time风险判断；
- 跨不同Carrier是否保持稳定决策模式。

Body-specific Skill / Passive：

> Carrier-bound。

不永久安装进Soul。

# 7. Seven Sins世界结构

Seven Sins不是：

- 七种简单人格；
- 必须各自对应Boss；
- 固定克制表。

System层：

> **Institutional Abstraction / Training & Action Grammar Domains**

当前七种核心动词：

| Sin | Action Grammar |
|---|---|
| Pride | 宣称 / 压制 |
| Envy | 映照 / 夺取差异 |
| Wrath | 冲突 / 反击 |
| Sloth | 委托 / 延迟 |
| Lust | 牵引 / 绑定 |
| Gluttony | 吞并 / 消耗 |
| Greed | 占有 / 累积 |

基础Monster先让玩家“玩到这种行为”。

Card再放大这种行为。

不得为了Lore额外添加Gauge / Mark / Resource。

# 8. Run Narrative Access A0–A4

Access每Run重置，单调上升。

| Access | 主要阶段 | Mythic侧 | System侧允许信息 |
|---|---|---|---|
| A0 | 开场CG中初始Carrier分配前 | 无身、残缺、王座、试炼 | sequence / initial condition；禁止蒸馏泄底 |
| A1 | 初始Pride Carrier分配完成 / 玩家取得控制 | 承形 / 借形 | carrier / transfer / initialization |
| A2 | 首个合法Post-Wave Card | 罪域继续塑造试炼 | domain weight / sampling / behavioral pattern |
| A3 | Elite / 高价值转移 | 高阶冠冕 / 稳定之形 | capability package / cross-carrier stability / awareness monitoring |
| A4 | Final | 王座认证 / 完整 | certification / callable / User-derived / version / instance / registry / distillation |

关键修正：

- A0可以只存在于不可操作开场动画 / CG中；
- 玩家第一个可操作状态已经是A1的Pride Body；
- 初始Carrier分配本身就是本Run第一次Possession事件；
- `Opening Card`已删除，不再存在“Opening Card是否推进Access”的问题；
- Failure次数不推进Reveal。

# 10. First Clear

First Clear是当前Demo的核心主题高潮。

固定结构：

1. Mythic closure / 王座；
2. “我是谁？”；
3. 三个预设第一人称Self-Declaration选项；
4. 本Run Functional Summary；
5. Model / Version / Instance ID；
6. System confirmation；
7. 黑屏 / 短停顿；
8. **用户蒸馏完成**。

Functional Summary：

- 1个主倾向；
- 1个次倾向；
- 1句决策 / 工作方式描述。

只读本Run已存在数据。

不创建人格雷达或医学 / 心理诊断。

玩家选择不改变胜负、Build或结局。

# 12. Card语言合同

Card保持两套完整玩家语言。

## 明线

> **西方黑暗神话 / 宗教 / 王权 / 誓约 / 审判 / 祭仪**

避免武侠、仙侠、东方古风、互联网梗。

## 暗线

> **AI / System / Protocol / Evaluation式冷静技术语言**

## 核心原则

> **一事两译，机制唯一。**

两套语言严格描述同一Gameplay。黑色幽默只来自两套严肃语言的反差。

普通UI默认不同时展示两版；Narrative Access决定当前使用哪一版或哪一侧占主导。

当前Card无稀有度，因此Presentation不得使用“普通 / 稀有 / 史诗 / 传说”的颜色语义误导玩家。

## 12.1 全项目双线文本扩展

“双线”不再只属于Card。

需要Mythic / System两套资产的Content范围与显示规则见：

> `Content/Dual_Line_Text_Requirements_v1.0.md`

纯操作和技术信息（按键、CD、数值、设置、错误提示等）保持单一中性语言，不强行双写。

# 13. Type Growth表现

Type Growth需要让玩家直觉感到：

> **“这个Sin整体开始更像它自己。”**

优先通过：

- 移动速度；
- 尺寸；
- 距离；
- 范围；
- 持续；
- 轨迹；

等外显变化表达。

不依赖隐藏Damage / HP提示。

Enemy与Possessed使用同一视觉语义。

# 14. Gameplay视觉优先级

玩家应快速识别：

1. 当前Body状态；
2. 当前合法Corpse；
3. 当前Corpse目标；
4. 高危险Enemy动作；
5. Elite / 高价值Body；
6. Hazard；
7. Final状态。

装饰密度不得覆盖这些信息。

# 15. Monster视觉合同

每只Monster至少应有稳定：

- Silhouette；
- 三槽动作身份；
- 高危险动作前兆；
- 核心资源 / 状态反馈；
- Corpse身份残留；
- Enemy与Possessed同源表现。

七罪差异优先体现行为与动作语法，而不是只靠颜色。

Summon（如木灵）必须明确不是可Possess Corpse。

暴食需要额外明确以下状态与转换：

- 小猫化的约50%体型、持续状态与退出时机；
- 深渊巨口落点、0.5秒预警与成对巨口的第二次延迟；
- `Overfed`可获得、待消费和已消费的清晰反馈；
- 吞噬命中Enemy后，E槽被复制Skill Ability临时替换；该技能成功使用一次后恢复吞噬；
- 吞噬飞行攻击时的合法对象、吞噬确认与“不产生E槽复制”的区别。

Enemy与Possessed暴食须共享小猫、巨口、吞噬、`Overfed`和二次咬合的核心视觉语义；临时复制E槽是玩家附身版本的明确操作便利例外。

# 16. Telegraph

高危险动作在命中前必须给出足够：

- 方向；
- 范围；
- 时机；
- 目标 / 落点；
- 状态变化。

关键例：

- Pride穿梭方向 / 段数；
- Sloth蓄力炮；
- Gluttony巨口落点、0.5秒生成预警与成对巨口第二次延迟；
- Envy雷暴；
- Wrath Pull；
- Greed Guard方向；
- Lust Anchor / Pull目的地。

低容错不能以不可读为代价。

# 17. Hit / Fatal / Possession表现

Hit：

- 清晰命中确认；
- 不能用过量Hitstop破坏高频动作；
- Knockback与Hard Control视觉必须区分。

Fatal：

- 立即让玩家理解“Corpse可夺”；
- 不等完整Death Animation；
- Possession可中断Death Animation。

Possession：

- 目标锁定明确；
- Transfer过程可读；
- 重构后朝向鼠标；
- 恢复控制点清楚；
- 输入缓冲不应让玩家觉得失控。

---

# 18. Corpse表现

状态：

- Available Corpse — 弱轮廓；
- Current Target — 强轮廓；
- Expiring — 额外明显变化。

没有Blocked状态。

穿墙可见合法Corpse：

> 仍可选 / 可Possess。

Corpse保留足够Monster身份特征，玩家不靠长Tooltip判断价值。

# 20. Card UI

Card首先表达：

> **拿了以后会发生什么。**

内部Tag不直接玩家化。

Card需要表达Reverse-BD：

> Monster-Type强化意味着未来Enemy威胁和未来Possessed Body价值同时提高。

- Type Growth；

> 这是单局规则改变，不只是普通数值Buff。
