# 1. Presentation Truth Boundary

本文件定义：

> 游戏应该如何被玩家看见、听见、理解，以及世界如何解释Gameplay。

优先级：

> **Gameplay Readability > Narrative Decoration**

Repository中的现有模型、材质、VFX、UI框架只证明“已经制作过”，不自动成为最终表现方向。

Presentation不得静默修改Frozen Gameplay。

---

# 2. 世界核心真相

当前隐藏的真实Run过程：

> **User Distillation / 用户蒸馏**

这是一个虚构Composite AI Process，用来表达：

- 行为学习；
- 模仿；
- 能力抽取；
- 跨载体适应；
- 判断方式；
- 工作 / 决策风格；
- 版本验证；
- 认证与注册。

它不是现实世界某个标准算法的逐字复刻。

# 3. 明线与暗线

## 3.1 Mythic明线

明线是：

> **Meaning / Goal Elicitation Layer**

它不是纯骗局。

它真诚地给Candidate提供：

- “我尚未完整”的意义；
- “借Body存续”的现实需求；
- “通过试炼抵达王座”的目标；
- 七宗罪作为试炼法则；
- 完成 / 加冕 / 作证的神话语言。

明线必须足够成立，让玩家能够带着真实目标做选择。

## 3.2 System暗线

暗线描述同一Gameplay的真实功能：

- Candidate；
- Carrier；
- Transfer；
- Standardized Initialization；
- Behavior Acquisition；
- Structured Sampling；
- Cross-Carrier Stability；
- Awareness Stress；
- Certification；
- Version；
- Instance；
- Registry；
- Distillation。

System语气：

> 冷静、礼貌、程序化。

不写成：

- 邪恶AI反派；
- 公司恶搞；
- 嘲讽玩家；
- Meme；
- 办公室喜剧。

## 3.3 两条线的关系

两条线不是“两种同等宇宙真相”。

> **System层是隐藏功能真相；Mythic层是系统用于引出意义与目标、并被Candidate真实体验的表层结构。**

Reveal是设计好的Milestone，不是Glitch。

## 3.4 Voice Delivery

当前Demo使用两个独立Presentation Voice Channel：

- `Mythic Voice`：众神 / 神谕式声音，承担Meaning / Goal Elicitation；
- `System Voice`：冷静、礼貌、程序化的电子声音，承担隐藏功能真相。

两个声音：

- 不自动定义为两个独立世界实体或人格；
- 不争论、不吐槽玩家、不形成善恶对话；
- 可以先后描述同一Gameplay事实；
- 最终本体关系保持Open。

首个成功Run必须交付System / Certification / Version / Instance / User Distillation核心功能真相；后续Run仅通过Certified Lineage / Version Trials低频深化，不重复第一次反转。

旁白数量、台词、音频与具体触发事件保持配置化。详细Delivery Contract见：

> `Content/Narrative_Voice_Delivery_Baseline_v1.0.md`

# 4. Tone

整体基调：

> **Dark + Sacred + Absurd + Cold Black Humor**

一句话：

> **庄严外表 + 荒诞制度**

黑色幽默不靠主动讲笑话。

它来自：

> 同一个行为在Mythic层被解释为神圣试炼，在System层被解释为冷静、正常、制度化的处理流程。

# 5. Soul / Body / Corpse世界合同

Soul最低身份：

> **Human / User-derived first-person Candidate Subject**

确认：

> Human provenance confirmed；Human identity open。

不确认：

- 它是否等于某个完整Original Human；
- 每个Version Trial是否是同一个“我”；
- Original Human最终本体。

Body：

> Capability Carrier / 临时承载形。

Enemy Fatal：

> Active Carrier原控制终止 → Transfer-Eligible。

Possession：

> Candidate接管Carrier。

满耐久 + 三槽Ready：

> Standardized Carrier Initialization。

主动离身旧Body崩解：

> Relinquished Carrier Termination。

自然衰减：

> Carrier Rotation压力的世界解释。

Lore不能用“系统就是这样”掩盖不公平Gameplay。

# 6. 高频换身的世界解释

高频换身：

> **Cross-Carrier Distillation**

系统观察：

- 选择哪具Body；
- 何时放弃；
- 三槽怎么组合；
- 如何Relay；
- 如何处理低耐久；
- Card选择；
- Elite价值判断；
- Bullet Time风险判断；
- 跨不同Carrier是否保持稳定决策模式。

Body-specific Skill / Passive：

> Carrier-bound。

不永久安装进Soul。

# 8. Run Narrative Access A0–A4

Access每Run重置，单调上升。

| Access | 信息层级参考阶段（非硬编码触发） | Mythic侧 | System侧允许信息 |
|---|---|---|---|
| A0 | 开场 / 初始Carrier分配前 | 无身、残缺、王座、试炼 | sequence / initial condition；禁止蒸馏泄底 |
| A1 | 初始Pride Carrier分配完成后的早期Run | 承形 / 借形 | carrier / transfer / initialization |
| A2 | 早期构筑与行为采样开始 | 罪域继续塑造试炼 | domain weight / sampling / behavioral pattern |
| A3 | 中局System显著进入 | 高阶冠冕 / 稳定之形 | capability package / cross-carrier stability / awareness monitoring |
| A4 | Final / Closure | 王座认证 / 完整 | certification / callable / User-derived / version / instance / registry / distillation |

关键修正：

- A0可以只存在于不可操作开场动画 / CG中；
- 玩家第一个可操作状态已经是A1的Pride Body；
- 初始Carrier分配本身就是本Run第一次Possession事件；
- `Opening Card`已删除，不再存在“Opening Card是否推进Access”的问题；
- Failure次数不推进Reveal；
- A0–A4继续定义信息权限，但具体由Wave、Elite、Card、Possession或自定义事件中的哪一个推进，属于可配置Delivery映射；
- Narrative Access、旁白Trigger和Card / UI Display Mode彼此解耦；
- Elite / 高价值转移仍是A3的合法候选条件与递进叙事窗口，但不再作为底层硬编码的唯一推进条件。

# 10. First Clear

First Clear是当前Demo的核心主题高潮。

固定结构：

1. Mythic closure / 王座；
2. “我是谁？”；
3. 三个预设第一人称Self-Declaration选项；
4. 本Run Functional Summary；
5. Model / Version / Instance ID；
6. System confirmation；
7. 黑屏 / 短停顿；
8. **用户蒸馏完成**。

Functional Summary：

- 1个主倾向；
- 1个次倾向；
- 1句决策 / 工作方式描述。

只读本Run已存在数据。

不创建人格雷达或医学 / 心理诊断。

玩家选择不改变胜负、Build、Functional Summary评分、结局或能力。Self-Declaration只表达玩家如何理解当前的“我”；程序预留三个可配置Text Key，可选保存选择供后续Recognition使用。

Functional Summary读取本Run原始统计，至少覆盖：

- 每个Sin的有效Body控制时长、Possession、三槽使用与Card投资；
- 主动离身、Death Relay、Soul / Shrine与低耐久换身；
- Bullet Time；
- Elite Fatal / Possession；
- Run时长、Wave与Final完成；
- 使用过的不同Sin数量。

主 / 次倾向权重、行为句式、阈值与平局处理必须配置化。Model / Version / Instance使用可替换模板生成，最终格式保持Open。

First Clear最低表现可复用Result UI、普通按钮、阶段文本与黑屏，不要求新场景、角色立绘、额外3D资产或复杂CG。

# 12. Card语言合同

Card保持两套完整玩家语言。

## 明线

> **西方黑暗神话 / 宗教 / 王权 / 誓约 / 审判 / 祭仪**

避免武侠、仙侠、东方古风、互联网梗。

## 暗线

> **AI / System / Protocol / Evaluation式冷静技术语言**

## 核心原则

> **一事两译，机制唯一。**

两套语言严格描述同一Gameplay。黑色幽默只来自两套严肃语言的反差。

普通UI默认不同时展示两版。具体版本由可配置Display Profile决定，可选择Neutral、Mythic、System或Follow Access，并可按界面覆盖。

Card ID、图标、分类、Gameplay效果与中性机制摘要始终稳定；Mythic / System名称与包装描述可以切换。已获得Card是否同步切换由配置决定，不要求在Canonical写死具体Access或事件节点。

当前Card无稀有度，因此Presentation不得使用“普通 / 稀有 / 史诗 / 传说”的颜色语义误导玩家。

## 12.1 全项目双线文本扩展

“双线”不再只属于Card。

需要Mythic / System两套资产的Content范围与显示规则见：

> `Content/Dual_Line_Text_Requirements_v1.0.md`

纯操作和技术信息（按键、CD、数值、设置、错误提示等）保持单一中性语言，不强行双写。

# 15. Monster视觉合同

每只Monster至少应有稳定：

- Silhouette；
- 三槽动作身份；
- 高危险动作前兆；
- 核心资源 / 状态反馈；
- Corpse身份残留；
- Enemy与Possessed同源表现。

七罪差异优先体现行为与动作语法，而不是只靠颜色。

Summon（如木灵）必须明确不是可Possess Corpse。

暴食需要额外明确以下状态与转换：

- 小猫化的约50%体型、持续状态与退出时机；
- 基础深渊巨口在脚下的0.5秒预警；`GL-A03`远程诱饵落点的预警与巨口生成；
- `GL-A01`成对巨口与`GL-A02`范围+100%可同时生效，两个巨口均需显示扩大范围；
- `Overfed`可获得、待消费和已消费的清晰反馈；
- 吞噬命中最近Enemy后，E槽被复制Skill Ability临时替换；该技能成功使用一次后恢复吞噬；
- `GL-S03`吞噬扇形内全部合法飞行攻击时的合法对象、全量吞噬确认与“不产生E槽复制”的区别。

Enemy与Possessed暴食须共享小猫、巨口、吞噬、`Overfed`和二次咬合的核心视觉语义；临时复制E槽是玩家附身版本的明确操作便利例外。

嫉妒需要额外明确以下状态与转换：

- 飞行1秒、+200%移速且不打断激光的状态反馈；
- 目标身上的Mark写入、20%伤害储存、`EN-R01`储存量+50%与写入效率提升、以及雷暴消费的完整反馈；
- `EN-A01`每3秒短暂四目标激光、`EN-M01`飞行路径Mark与`EN-A05`连续激光伤害爬升的可读区分；
- 锁链雷电传导至所有带Mark目标时的目标链路、独立结算与消费反馈；
- `EN-S01`追加雷霆仍应独立预警。

Enemy与Possessed嫉妒须共享Mark、雷暴传导与印记消费的核心视觉语义；玩家版本保留鼠标瞄准便利。

愤怒需要额外明确以下状态与转换：

- 钩索位移的方向、合法落点、路径伤害与抵达落点冲击；
- 双拳砸地的范围、燃烧区域与Greed黑油被点燃的状态变化；
- 低耐久`WR-B01`的伤害、攻击范围与Attack CD缩短反馈，三项均需有最大50%的可读上限；
- `WR-B02`贴身燃烧光环的边界与敌人被点燃确认；
- 暴怒锁链龙卷风的2秒持续、每0.5秒结算、+300%移动速度与`WR-S03`额外+2秒时长。

Enemy与Possessed愤怒须共享钩索、砸地燃烧、黑油点燃、龙卷风Pull与低耐久强化的核心视觉语义。

贪婪需要额外明确以下状态与转换：

- 黑油向前释放的长度、范围、玩家加速区域，以及`GR-M01`赋予Enemy减速后的状态差异；
- 魔手每秒生成、环绕库存、0.2秒依次释放、击杀后再索敌及生成1–2只新魔手的实例上限反馈；
- 全伤害Guard的吸收量、1秒基础窗口、不能移动、每100伤害转1手，以及`GR-S01`每60伤害转1手的资源转化反馈；
- `GR-S04`3秒Guard、主动提前结束与立即进入Reload的HUD、VFX与结束反馈；
- `GR-M02`自身普通黑油上的地形伤害隔离，以及`GR-A07`魔手侧翼路径预览；
- 魔手击杀派生不得递归，并须保持Enemy与Possessed的核心视觉语义一致。

Enemy与Possessed贪婪须共享黑油、魔手击杀派生与全伤害Guard资源转化的核心视觉语义。

# 17. Hit / Fatal / Possession表现

Hit：

- 清晰命中确认；
- 不能用过量Hitstop破坏高频动作；
- Knockback与Hard Control视觉必须区分。

Fatal：

- 立即让玩家理解“Corpse可夺”；
- 不等完整Death Animation；
- Possession可中断Death Animation。

Possession：

- 目标锁定明确；
- Transfer过程可读；
- 重构后朝向鼠标；
- 恢复控制点清楚；
- 输入缓冲不应让玩家觉得失控。
