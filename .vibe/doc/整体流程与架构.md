## 1. 整体运行时流程

```
启动（BootStrapper 静态引导 + FontApplier 字体注入）
  └─ MainMenu 场景（MainMenuController + SoulMenuShowcase 灵魂展示 + 图鉴/名人堂入口）
       └─ 开始游戏 → 进入对局场景（如 EnemyAiTest / 正式 Arena 场景）
            ├─ ENGPOSS001SceneInstaller：场景安装器（Awake 初始化各场景组件）
            ├─ UIManager（SceneSingleton）初始化，聚合 UI 面板/按钮
            │    └─ EnsureBuildView()：FindObjectOfType<BuildView>() 发现场景中挂载的 BuildView
            ├─ WaveManager 波次流程（读取 Run 存档可 resumeFromWaveIndex）
            │    ├─ Initialize() → StartWaves()
            │    ├─ RunSpawnDirector / MonsterSpawner 连续刷怪（AnimationCurve 难度乘数）
            │    ├─ 每波完成 → autoShowChoiceUI 打开 CoreChoiceUI 选卡 → CardManager 获得卡
            │    └─ Boss（Sevenfold）→ 终局（无提前胜利）
            ├─ 附身系统（PossessionManager）：灵魂 → 附身怪 → 换身 / 脱离 / 附身怪死亡
            │    └─ BuildView 轮询附身状态，实时刷新构筑
            ├─ 构筑显示 BuildView（BuildButton 三态循环）
            │    0 迷你卡条（常驻 HUD） / 1 扇形放大（暂停） / 2 隐藏
            ├─ 局外采集：CardArchiveTracker 挂 GameManager（订阅 CardManager 事件）
            └─ 结束返回 MainMenu
```

要点：
- **ENGPOSS001SceneInstaller** 是当前对局场景的“安装入口”，负责在 Awake 里把场景组件接上（如 MonsterSpawner 初始化）。
- **UIManager 不创建** BuildView，只“发现并持有”场景中已挂载的组件（`EnsureBuildView` → `FindObjectOfType`）。
- 卡牌数据源是 **CardManager**，BuildView 只读渲染；附身状态变化由 `BuildView.Update` 轮询 `PossessionManager` 实时刷新。
- 图鉴数据采集由 **CardArchiveTracker**（挂 GameManager 常驻）订阅 `CardManager` 事件驱动，与主菜单图鉴面板共用 `CardArchiveStore`。

## 2. 架构分层

| 层 | 代表 | 职责 |
|---|---|---|
| 核心协调 | `GameManager`（单例，DDOL） | 游戏状态 / 玩家引用 / 敌人计数 / 调试组件挂载点 |
| 流程层 | `WaveManager` / `ENGPOSS001SceneInstaller` | 单局波次推进、场景安装 |
| 系统层 | `Combat/*`、`Possession/*`、`Levels/*`、`Elite/*`、`Meta/*`、`Save/*` | 玩法系统实现 |
| UI 层 | `UI/Core/UIManager` + `UI/Gameplay|HUD|MainMenu|HallOfFame|CardArchive|Narrative` | 所有界面与 HUD |
| 内容层 | ScriptableObject（`CardData`/`CardLibrary`/`MonsterAIConfig`/`WaveDefinitions`/`ArenaConfig`/`RoomTemplate`…） | 数据驱动配置 |
| 持久层 | `SaveCoordinator`（Run 存档）+ `MetaProfileStore`（局外 meta 存档） | 读写分离 |

依赖方向：内容层 ← 系统层 ← UI 层；UI 通过持有引用 / `FindObjectOfType` 接入；系统层经事件或单例暴露数据。

## 4. 核心子系统详解

### 4.1 卡牌系统（`Levels/Rooms/`）

| 文件 | 职责 |
|---|---|
| `CardData.cs` | 单卡数据（effectId、卡名、描述、多层 sprites、targetAbilityTags、category/monsterType） |
| `CardLibrary.cs` | 卡池 SO（cards 列表 + disabledEffectIds 退役 + OnValidate 查重） |
| `CardManager.cs` | 卡池管理、获得卡、抽卡候选（currentPicks）、事件总线 |
| `CoreChoiceUI.cs` | 选卡弹窗（提供 cardPrefab，卡片交互） |
| `CoreChoiceCard/ChoiceCard.cs` | 选卡卡片 UI 组件 |

**事件（2026-08 新增，图鉴采集挂点）**：
- `CardManager.OnCardOffered`：候选落定（Offer）
- `CardManager.OnCardRerolled`：重抽后候选变化
- `CardManager.OnEffectUnlocked`：获得/解锁卡（同时写入 `MonsterAIConfig.IsUnlocked` 钩子）

**卡面图标（2026-08-26）**：`CardLibrary` 49 张 active 卡的 `image` 已替换为 `Resources/UI/MonsterSkillIconConfig.asset` 中对应技能的图标；槽位按卡的 `targetAbilityTags` → 对应 `EnemyAbility.type`（普攻/技能/位移）判定，特殊卡（Passive 的 `BurnAura`、TypeGrowth 无具体能力）按技能图标兜底。

### 4.2 怪物 AI（`AI/` + `Core/Control/AIController.cs`）

- **配置**：`MonsterAIConfig.asset`（SO，7 只 `_new` 怪：Gluttony/Lust/Pride/Envy/Sloth/Wrath/Greed），每条 `MonsterAIConfigEntry` 含索敌/攻击/技能范围、决策节拍、行为权重、追击走位等。
- **行为树**：`AIController` 挂载在 `MonsterActor`，`BuildTree()` 用 `BTSelector/BTSequence/BTCondition_*` 组装（攻击分支 / 追击分支 / 待机）。
- **动态范围（2026-08 新增）**：`MonsterAIConfigEntry.rangeUnlocks`（`List<AIRangeUnlock>{unlockId, basicAttackRange, skillAttackRange}`）；运行时 `MonsterActor` 的攻击/技能范围 getter 实时取 `max(基础值, 已解锁覆盖)`，解锁判定走 `MonsterAIConfig.IsUnlocked`（`CardManager` 注入 `unlockedEffects.Contains`）。当前 Pride 配置 `PR-A04`（Sword Qi 射程 3→15）。
- **编辑器**：`MonsterActor.aiConfigId` 用 `AiConfigIdAttribute` + `AiConfigIdDrawer` 做下拉选择（防手填拼错）。

### 4.3 波次与刷怪（`Levels/Waves/` + `Levels/Spawning/` + `MapStreaming/MonsterSpawner`）

- `WaveManager`：波次调度（`Initialize/StartWaves`、读档 resume、`autoShowChoiceUI` 弹卡、潮汐、精英注入、Boss）。数据源 `WaveDefinitions`。
- `RunSpawnDirector`（**2026-08 重构**）：连续刷怪导演。原“周期压力/击杀回声窗口”机制已**删除**，改为 **AnimationCurve 难度乘数**（`ConfigureRunTiming(nonBossSeconds, growthIntervalSeconds, healthCurve, attackCurve)`；`CurrentHealthMultiplier/CurrentAttackMultiplier` 实时求值）。
- `MonsterSpawner`（`MapStreaming/`）：场景刷怪，`InitAiRng(spawnSequence++)` 给每只怪分配 AI 种子。
- `MonsterPool` / `SpawnRequest` / `MonsterSpawnDifficulty`：刷怪池/请求/难度。

### 4.4 地图流式（`Levels/MapStreaming/`）

- `MapStreamingSystem`：系统入口（`InitBoundary` 等），驱动 Chunk 流式生成。
- **双层 Tile 模型**（`TileData`/`ChunkTileGenerator`/`FixedChunkLayout`）：`BaseLayer` 底层地砖 + `StructureLayer` 可选叠加装饰/结构（对齐设计 §2.2）。
- `ChunkRuntime`：Chunk 运行时实体。
- `TerrainEffectTile` / `TerrainSpikeHazard`：地形效果（GameplayEffectDefinition 驱动）与尖刺伤害。

### 4.5 附身系统（`Combat/Possession/PossessionManager.cs`）

- 状态机：`Idle → Possessing / Flying → …`，`CurrentBody` 当前附身怪。
- 事件：`OnPossessionStarted(MonsterActor)` / `OnPossessionEnded()` / `OnPossessionEndedEx(reason)` / `OnBodyDiedWhilePossessing(MonsterActor)`。
- 消费方：`AbilityCooldownUI`（三槽图标/CD）、`BuildView`（构筑）、怪物 AI（附身期间接管）。

### 4.6 构筑显示 BuildView（`UI/Gameplay/BuildView.cs`）

- 自包含组件，挂 `UICanvas` 下；三态循环（BuildButton）。
- **场景挂载（2026-08）**：`UIManager.EnsureBuildView` 改为 `FindObjectOfType<BuildView>()` 发现场景中手动挂载的组件（不再运行时自建）。
- 默认值对齐场景配置：`miniScale=0.15 / miniSpacing=60 / miniAnchor=(60,-80)`；迷你空态提示锚定 miniBar 左上角（跟随 miniAnchor）。
- **附身实时刷新（2026-08）**：`Update` 轮询 `PossessionManager.CurrentBody/State`（与 `AbilityCooldownUI` 同模式），附身/脱离/换身/死亡时实时刷新当前模式构筑。

### 4.7 局外系统（`Systems/Meta/` + `Systems/Elite/` + `Systems/Save/`）

- `MetaProfileStore`：局外 meta 存档（`possess_meta_save.json`，schemaVersion=1，版本不符保留 `cardArchive` 段）。含 `CardArchive`（图鉴）+ `ValidCardTotal`。
- `CardArchiveStore` + `CardArchiveTracker`：图鉴三态采集（Offer/Reroll→Known、Unlock→Unlocked、selectedCount 累计；分母=有效卡总数）。`CardArchiveTracker` **挂 GameManager 常驻**（2026-08 修复：不再用 `RuntimeInitializeOnLoadMethod` 自建，避免无域重载下静态 instance 悬空）。
- `CardArchivePanel`（`UI/CardArchive/`）：纯代码 UGUI 图鉴面板（三态渲染、页签、NEW 角标、打开清未读）。**2026-08-26 修复**：CanvasScaler 配置 1080p 参考缩放（4K 适配）、动态 TMP 文本应用中文字体、EnsureInstance 自愈（防半成品）、补 GraphicRaycaster（按钮可点）。**待办：卡片 tile 目前只渲染文字，卡面 image 未接入**（已知缺口）。
- `HallOfFameStore`：荣誉殿堂（schemaVersion 前向兼容，版本不符保留条目）。
- `SaveCoordinator`：Run 存档（`possess_run_save.json`），`DeleteSave` 只删 run save，**不触碰 meta 文件**。

### 4.8 UI 与调试

- `UIManager`（`UI/Core/`）：UI 总控，聚合面板/按钮，`EnsureBuildView = FindObjectOfType`。
- `AbilityCooldownUI`（HUD）：三槽技能图标 + CD（用 `MonsterSkillIconConfig` 取图）。
- 调试面板（多挂 `GameManager`，由 `GameManager.Start` 统一 `EnsureOnGameManager`）：`CombatHitboxDebugSettings`、`AudioDebugPanel`、`NarrativeDebugPanel`、`CardArchiveTracker`、（编辑器/开发包内）`CardFaceBrowser`。`MapDebugHUD`/`CardProgressPanel` 仍是 `RuntimeInitializeOnLoadMethod` 自建模式（同款隐患，未改）。
- `CardFaceBrowser`（`Debug/`，F3）：卡面浏览器，4K 下 OnGUI 按 `Screen.height/1080` 等比缩放。

## 5. 持久化与存档

| 存档 | 文件 | 管理 | 生命周期 |
|---|---|---|---|
| Run 存档 | `possess_run_save.json` | `SaveCoordinator` | 单局进度（波次/获得卡/候选快照）；新局覆盖、`DeleteSave` 删除 |
| 局外 meta 存档 | `possess_meta_save.json` | `MetaProfileStore` | 跨局长期（图鉴、有效卡总数）；**与 Run 存档物理分离，新局/读档不触碰** |

## 6. 需求（Canonical）与实现对照

| 项 | Canonical 基线 | 实现状态 | 差异/备注 |

| 三槽输入/附身 | 高频换身、Body/Soul/Corpse | ✅ PossessionManager + BuildView 实时刷新 | 一致 |
| 教学/旁白 | Tutorial / Narrative Baseline | 🔍 未在本快照深入 | 见对应 Baseline 文档 |
