# Possession — 项目设计入口

> 《Possession》正式设计真源入口：[`Canonical/00_CANONICAL_INDEX.md`](Canonical/00_CANONICAL_INDEX.md)。
>
> 发生设计冲突时，以 Canonical Index 定义的 Authority Order 为准。

## 1. 正式设计读取顺序

设计、策划、内容或表现相关工作按以下顺序读取：

1. [`Canonical/00_CANONICAL_INDEX.md`](Canonical/00_CANONICAL_INDEX.md)
2. `Canonical/01_DESIGN_CANONICAL.md`
3. `Canonical/02_CONTENT_CANONICAL.md`
4. `Canonical/03_PRESENTATION_CANONICAL.md`
5. 按任务范围读取 `Canonical/Content/` 下的详细真源或 Baseline
6. 最后读取 Repository 实现事实和旧模块文档，用于理解现状与后续 Gap

核心边界：

> **Repository Fact ≠ Design Truth**

## 3. 旧 Modules 的定位

`.vibe/doc/Modules/` 完整保留，用于：

- Historical Reference；
- 当前 Repository Implementation Reference；
- 追溯既有怪物流水线、配置与实现上下文。

旧 Modules、旧 Demo、旧 Card、旧 Monster、旧 Room 或当前 Repository 行为不得覆盖 Canonical。

怪物实现上下文仍可从 [`Modules/Monsters/README.md`](Modules/Monsters/README.md) 和 `.vibe/shared-skills/monster-dev-pipeline/SKILL.md` 进入，但二者不是新的正式设计 Authority。

## 4. 后续阶段边界

Canonical 入库不等于 Legacy Audit、Migration、Architecture Alignment、Production PM 或 Gameplay Implementation。相关工作必须按当前团队流程在对应 Human Gate 后单独执行。
